# IDD-0012.spec-factory-recovery-and-refinement

## Intent

Factory preserves recoverable temporary work and the authority of approved Product Intent across interruptions. IDD-0001 owns orchestration and entry modes; this spec owns persisted state, provenance, recovery and refinement review. The architecture rationale is in IDD-0006.

## Temporary state

Factory persists only lightweight, Git-ignored Markdown context, not an
execution engine. Shared task context may be stored once and referenced by
small work items rather than repeated in each assignment:

```text
.idd/factory/preparation/
    request.md               # complete original base request
    baseline.md              # immutable original full Git HEAD, repo identity
    provenance.md            # bounded authorization/Worker checkpoints
    answers.md               # verbatim chronological Q/A, optional
    question.md              # pending exact question, optional
    verification-failure.md  # bounded final-check diagnostic, optional
.idd/factory/current/
    plan.md                  # validated remaining tasks before activation
    baseline.md              # unchanged original baseline
    provenance.md            # preflight and Worker attribution boundaries
    answers.md               # preserved Q/A, optional
    request.md               # sole active-run marker, written LAST
    completed.md             # later bounded worker summaries
    question.md              # later question, optional
    verification-failure.md  # later bounded failure, optional
```

An existing directory or an orphaned plan without the marker is not an active
Factory run. On continuation prefer an existing active marker; otherwise restore
valid preparation and its exact pending question without inheriting a transcript.
A new independent request cannot silently merge with that preparation. Explicit
cancellation removes preparation, not durable Product Intent or Engineering.
An interrupted activation must not trust partial inactive files without
verifying their provenance against saved preparation. A marker must not be
replaced to bypass Engineering guardrails.

The repository is authoritative implementation reality. `request.md` holds
the unchanged full base request; `answers.md` preserves exact Q/A separately;
`plan.md` contains only remaining tasks. Activation writes a valid plan and
answers BEFORE the marker and does not launch a Worker beforehand. Valid initial
Tasks are not re-planned merely because activation succeeded. No transaction,
locks, exactly-once promise, retry counter or runtime state schema is added.

## Immutable Git baseline, provenance and safe recovery

Only **new independent** Factory runs require clean managed IDD paths
(`.idd/intent/`, optional `.idd/engineering/`) and a valid Git HEAD.
Detect all tracked staged, unstaged, renamed/deleted and nonignored untracked documents without path-name ambiguity. Existing dirty code/tests
elsewhere do not block start. After non-mutating request blocker checks,
save original complete request, full immutable HEAD, sanitized minimal
repository identity and bounded before-action provenance **before any**
Engineering/Product owner writes. Recheck cleanliness before mutation if
necessary. Never auto-commit to establish cleanliness or invent a baseline.

Capture action boundaries for Engineering/Product owner workflows and Workers:
phase, owner/action, affected IDD documents, HEAD and bounded hashes/hunks,
exact user request or saved Q/A authorization and result. Provenance supports
review but does not constitute another history system or automatic proof of
origin. A crash between mutation and its after-boundary leaves
`external-unknown` changes, not an automatically approved document. The
effective contract is original obligations plus explicit authorized owner
changes; Worker refinements cannot independently alter it. Commits, new
working-tree diffs and pre-existing dirty code are not attributed by guess.

Continuation from active or saved preparation never requires clean Git or a
new commit, never replaces initial baseline, and never blindly replays an
owner. Inspect saved pending checkpoints and actual current files; preserve
partially completed or external work. Partial activation must validate plan,
baseline, provenance and answers before writing the sole active marker
`current/request.md` last. A previous Writer confirmed still active prevents
a second Writer; a pending checkpoint or aborted transcript alone does not
establish such activity. Legacy pre-baseline runs retain original no-Intent-write
semantics; baseline loss in a new run is corruption, not permission to
manufacture HEAD. Active replacement inherits original baseline and dirty
changes with known/unknown provenance; it cannot evade the new-run gate.

## At-least-once execution and abnormal interruption

Factory uses at-least-once execution and semantic convergence, not
exactly-once effects. Interrupted Tasks remain pending in `plan.md`; a later
fresh Worker examines actual repository state and preserves correct partial
work before finishing the remainder.

Normal handoffs need trusted successful native terminals and verified
Task/plan checkpoints, not an OS process-tree proof. A native wait returning
`timed_out: true` means only that its interval ended; the wait tool's own
`completed` status is not child completion. If the SAME child is active,
re-arm long native blocking waiting without interrupting it or spawning a
new Writer. Never treat one interval expiration as CHILD_UNCONFIRMED or
automatically cancel a healthy child. On genuine host failure, explicit
interruption or unresolvable child identity, preserve Factory state and Git
changes and block further Writers until the old operation is resolved.
Factory does not implement recursive kills, frequent model-driven polling
or cancellation test harnesses. The host owns OS process cleanup.

A BLOCKED response must present a comprehensible cause, what is preserved
and safe next steps under existing entry modes: Continue the saved request
(with reconciliation and possible replanning), explicit Restart/replacement,
Cancel then New only after safe cleanup, or manual inspection when an old
Writer may still run. These are suggestions, not automatic recovery actions.
Supervisor must not claim to know nested child state when its Root has no
trusted terminal. No new lifecycle status, persisted recovery state or
Factory-owned process supervisor is added.

A later **explicit** Continue/Restart/Cancel requires the previous top-level
host turn to have ended and no surviving active Writer according to host
lifecycle/native child evidence. After quota exhaustion or another aborted
turn, Continue should autonomously reconcile pending provenance against Git
reality and resume remaining Tasks. An incomplete checkpoint or untrusted
terminal prevents counting a Worker as completed, but is NOT by itself proof
that it still runs. Do not require manual OS process inspection by default.
If an old Writer is observed active, or host liveness is specifically
unresolved, remain BLOCKED with concrete evidence and request host-side
inspection rather than overlap Writers. Unrelated New requests must
explicitly resolve unfinished work first. Completed-plan boundaries permit
optional external Git commits and architecture reviews, but Factory never
auto-commits, silently discards work or creates new persistent lifecycle
states.

## Monotonic Intent Refinement and final review

Only Factory Worker may update already existing owning `IDD-NNNN`
specs, Living ADRs or active spikes with verified durable findings while
implementing its assigned Task. It checks existing owner, entailment from
approved obligations or reproducible technical evidence, normative effects
and future value. No independent requirement, architecture reversal,
Acceptance Criteria change, Engineering Rule or new IDD owner may be added.
Absence of textual contradiction and passing tests alone are insufficient.
An explicit user no-document-change restriction wins. Avoid parallel
normative `doc/` or `docs/` documents; unchanged external originals can
remain as references under their original filenames.

Final review compares committed **and** uncommitted current Intent against
the immutable baseline, authorized owner before/after boundaries and Worker
checkpoints. Distinguish preflight-approved changes, later owner changes,
candidate Worker refinements and external/unknown modifications. Report
changed paths, meaningful findings and Git diff separately from the verified
Implementation Result. Users may accept all/some refinements, selectively
reject, request correction or defer. Rejecting a single refinement must not
blindly restore entire files or revert unrelated work; recheck current hunks
and implementation dependencies and rerun affected tests.

Deferred review preserves bounded evidence under ignored
`.idd/factory/results/`, not an approval database. It is worktree-local,
depends on Git object availability, and may be lost; pending review never
keeps `current/request.md` active or turns a new product decision into an
approved contract.

Completed temporary state may be archived best-effort under `.idd/factory/results/` or removed. The archive is diagnostic history, not serialized runtime state.

## Legacy runs

Legacy `.idd/factory/current/state.json` is not migrated or interpreted by the
new Factory. Product changes are never rolled back automatically. An explicit
restart may reuse a valid legacy `request.md` as the replacement request and
archive old state for diagnostics.

# IDD-0003.spec-core-intent-and-generation

## Intent

IDD keeps durable product memory compact and current while implementation workflow remains disposable. `idd-intent` is the standalone core plugin; `idd-factory` is optional and depends on it. Factory runtime behavior is owned by IDD-0001.

## Product model

`.idd/intent/` contains current specs, ADRs, and active spikes; Git stores history. Tasks, progress, plans, review notes, and generated reports are not intent. `GLOSSARY.md` is optional and contains only terms whose ambiguous interpretation could materially change understanding; it is not a general dictionary.

`src/canonical/` is the source of truth for distributable IDD content. `plugin-manifest.json` defines logical plugins, dependencies, skills, references, assets, and plugin metadata. `skill-descriptions.json` defines skill descriptions, manual/automatic invocation policy, and adapter-specific front matter; for Claude this includes details such as context, agent, argument hints, and `allowed-tools`. `src/adapters/claude/adapter.json` and `src/adapters/codex/adapter.json` describe host entry points and adapter capabilities.

The generator validates these inputs, packages the Factory runtime, and produces Claude and Codex marketplace/plugin artifacts from the same canonical skill bodies. Platform adapters may change packaging, front matter, launcher mechanics, and host-specific metadata, but not canonical meaning. Generated output is derivative and must not be maintained as a separate source. Generated plugin metadata records the platform/version and points back to `src/canonical` as the canonical source.

Factory work items and active state are temporary, Git-ignored operational artifacts. Successful finalization clears active state; retained diagnostics do not become intent automatically. Shared task context may be stored once and referenced by small work items to avoid repeating common instructions.

## Self-hosting

This repository defines IDD and uses IDD to describe itself. `.idd/intent/` states product intent; `src/canonical/` implements the distributable method; runtime/adapter/generator code implements execution and packaging; generated plugins are output only. For changes to IDD itself, update the smallest owning intent document when durable behavior changes, then update implementation. Do not recursively bootstrap IDD from its own generated plugins or regenerate self-intent from implementation.

# IDD-0003.spec-core-intent-and-generation

## Intent

IDD keeps durable product memory compact and current while implementation workflow remains disposable. `idd-intent` is the standalone core plugin; `idd-factory` is optional and depends on it. Factory runtime behavior is owned by IDD-0001.

## Product model

`.idd/intent/` contains current specs, ADRs, and active spikes; Git stores history. Tasks, progress, plans, review notes, and generated reports are not intent. `GLOSSARY.md` is optional and contains only terms whose ambiguous interpretation could materially change understanding; it is not a general dictionary.

`src/canonical/` is the source of truth for distributable IDD content. `plugin-manifest.json` defines logical plugins and their skills/assets. `skill-descriptions.json` defines skill descriptions, invocation policy, and adapter-specific metadata. `src/adapters/claude/adapter.json` and `src/adapters/codex/adapter.json` describe host-specific packaging capabilities.

The generator produces Claude and Codex artifacts from the same canonical content. Platform adapters may change packaging, front matter, and launcher mechanics, but not canonical meaning. Generated output is derivative and must not be maintained as a separate source.

Factory work items and active state are temporary, Git-ignored operational artifacts. Successful finalization clears active state; retained diagnostics do not become intent automatically.

## Self-hosting

This repository defines IDD and uses IDD to describe itself. `.idd/intent/` states product intent; `src/canonical/` implements the distributable method; generated plugins are output only. For changes to IDD itself, update the smallest owning intent document when durable behavior changes, then update implementation. Do not recursively bootstrap IDD from its own generated plugins or regenerate self-intent from implementation.

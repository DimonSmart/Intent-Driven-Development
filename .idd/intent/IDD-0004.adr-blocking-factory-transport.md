# IDD-0004.adr-blocking-factory-transport

## Status

Accepted

## Context

Factory can run for many minutes while workers, builds, tests, and reviews execute. When a host launches the runtime through a shell and returns control to the model, periodic status checks waste model turns and tokens without adding semantic work.

## Decision

`idd-factory-run` remains transport-neutral, but one Factory invocation must behave as one blocking transport operation rather than a model-driven polling loop.

Codex currently uses the Factory plugin's bundled MCP transport around the packaged runtime. The skill must not fall back to shell polling when that transport is unavailable. Claude may use the packaged CLI when its host can wait for process exit with the required lifecycle boundary.

MCP is adapter infrastructure, not a permanent Factory Core dependency. A future native Codex mechanism may replace it if it can block without model polling, propagate cancellation, clean up the owned process tree, and return the same structured runtime result without changing Factory state or workflow semantics.

## Consequences

Transport cost should not grow merely because deterministic work takes longer. Release checks must verify blocking behavior, interruption cleanup, and resumability. Transport replacement remains adapter work when runtime contracts are preserved.

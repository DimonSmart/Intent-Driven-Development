# IDD-0002.adr-runtime-owns-workflow

## Status

Accepted

## Context

Factory must execute large tasks whose later work can be unknowable until
earlier work produces repository changes, evidence, or semantic findings. A
mutable task graph can express that uncertainty, but it makes semantic agents
author persistent identities and cross-references, forces runtime to validate
and mutate topology, and introduces outline/refinement states that materialize
work before its contract is knowable.

The essential operational requirements are simpler: preserve completed work,
execute one known task at a time, put a newly discovered prerequisite before
the interrupted task, and replace the future strategy when evidence invalidates
it. None requires a DAG.

## Decision

The .NET 10 Factory runtime remains the sole owner of operational decisions. Its
authoritative execution model is:

```text
immutable Completed + zero-or-one Current + ordered Remaining
```

The scheduler always selects the first remaining task when no current operation
must be resumed. Semantic planning returns an ordered list of only the future
work currently known. Runtime assigns persistent IDs, creates immutable
contracts, validates capabilities, and persists the list atomically.

Completed work is immutable. If completed behavior later proves insufficient or
incorrect, planning creates corrective future work rather than reopening
history.

A worker-discovered prerequisite is a local ordered-list operation: runtime
prepends the new task and then the interrupted original task ahead of the prior
remaining tail. A genuine global strategy change is a full atomic replacement
of remaining work at a safe point. Semantic replanning never returns mutation
operations or changes completed work.

Initial planning, planning after newly learned facts, and global replanning use
the same flat semantic result shape. Planning may be deliberately partial; work
whose contract depends on future evidence is not materialized as an outline.

Intermediate review may be ordinary ordered semantic work. Mandatory final
integrated review is a terminal orchestration phase after strict deterministic
verification and is stored separately from planned work.

Runtime state uses a CAS `Revision`; any additional plan/product-snapshot
revision must not encode graph topology. Atomic state snapshots remain
authoritative. Optional plan-history artifacts are diagnostic provenance and
are never replayed for recovery.

Factory Core continues to depend on an agent-backend abstraction. Backend
adapters expose the selected skill and map execution profiles to platform
permissions; they do not own scheduling or plan mutation.

## Alternatives Considered

- Retain the mutable task graph while simplifying its protocol: rejected
  because dependencies, topology validation, graph revisions, and refinement
  lifecycle would remain without an essential runtime need.
- Use a classic LIFO stack: rejected because Factory needs ordered first-item
  execution, stable multi-item prepend order, and full future-plan replacement.
- Treat every discovery as global replanning: rejected because a concrete local
  prerequisite is handled deterministically by prepend with less semantic work.
- Restore an LLM coordinator: rejected because operational decisions are
  derivable from typed state and deterministic policy.
- Build a generic workflow/DAG framework: rejected because Factory needs a
  bounded domain runtime rather than a general orchestration product.
- Infer a linear migration for active graph runs: rejected because a safe order
  cannot be guaranteed for arbitrary persisted topology and partial state.

## Consequences

- There is no authoritative task graph, dependency edge, topological readiness,
  outline/refinement lifecycle, covered-work metadata, graph mutation protocol,
  graph cycle validation, or graph revision.
- Planner tasks contain only a registered capability and semantic contract;
  runtime owns IDs and execution bookkeeping.
- Runtime state validation focuses on identity uniqueness across completed,
  current, and remaining work, capability and contract validity, completed
  immutability, and legal atomic transitions.
- Factory can execute tasks that cannot be planned fully in advance by planning
  again after completed work supplies the missing facts.
- Runtime tests cover ordered scheduling, immutable completed history, atomic
  prepend/replacement, simple semantic protocol validation, exact crash
  recovery, deterministic verification, review correction, and finalization.
- Legacy active graph runs must finish with their previous runtime or be
  cancelled and restarted. Existing repository/product artifacts remain
  untouched.

## Supersedes

The dynamic-task-graph portion of the previous accepted version of this ADR.
Durable runtime ownership remains; the owned operational model is now the
linear completed/current/remaining state.

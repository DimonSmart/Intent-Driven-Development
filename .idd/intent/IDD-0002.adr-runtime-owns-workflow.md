# IDD-0002.adr-runtime-owns-workflow

## Status

Accepted

## Context

Factory must execute requests whose later work cannot be contracted until
earlier work changes the repository or produces evidence. The previous linear
runtime still asked executors and reviewers to classify semantic outcomes such
as additional work, correction, or global replanning. This made ordinary
workers participate in orchestration, required an outcome-specific schema
matrix, and forced runtime to interpret several kinds of plan mutation.

The runtime already owns deterministic state, ordering, verification, recovery,
and retries. One semantic authority can therefore answer the ordinary workflow
question: what work is safely contractable now?

A separate edge case remains: after all currently contractable work has been
executed, the planner can discover that further work requires a product or
implementation decision that neither the original request, current intent,
repository reality, nor prior evidence determines. Guessing that decision is
wrong, while forcing executors to emit orchestration outcomes would recreate the
old protocol.

## Decision

The .NET 10 Factory runtime remains the sole owner of operational transitions.
Semantic orchestration uses a repeating bounded-batch cycle:

```text
planner -> ordered batch -> sequential execution -> planner
```

The planner is the only semantic component that creates future work. It
examines the immutable original request, current durable intent, repository
state, completed task results, runtime-observed changes, authoritative
verification evidence, and prior user answers recorded by planning pauses. It
materializes all tasks that are reliably contractable now and stops before work
whose contract depends materially on new evidence. When semantic reassessment
finds no remaining work and no missing user decision, the planner returns
exactly `# Done`. Runtime validates that marker mechanically and maps it to the
existing empty-batch representation. Blank or whitespace-only planner output is
malformed and does not mean completion.

When no further task can be safely contracted because a decision must come from
the user, the planner may return one human-readable `# Question` section instead
of tasks. A question is allowed only when there is no task that should execute
before that decision. Planner output cannot mix tasks, a question, and `# Done`.

The runtime treats that question mechanically as a resumable
`USER_DECISION_REQUIRED` pause. It persists the question, returns it to the host,
and performs no further Factory work until an exact user answer is supplied or
the run is cancelled. The runtime does not decide whether the question is a
product decision, does not synthesize an answer, and does not edit durable
intent.

The outer IDD workflow evaluates the user's answer. When the answer changes or
adds durable product truth and the requested scope permits intent writes, the
ordinary intent workflow records and validates that truth before Factory
resumes. When the answer is only an implementation choice, durable intent
remains unchanged. If durable intent must change but the requested scope forbids
that write, the run remains paused until the scope permits the intent update or
the user cancels it; the answer must not be reinterpreted as an implementation
choice. After any required intent work is complete, the exact answer is passed
back to the same Factory run, stored separately from immutable `request.md`, and
supplied to later planning cycles. If the user declines to continue, the run is
cancelled explicitly.

The runtime assigns identities, atomically adopts each batch, executes every
task in order, verifies workspace-writing tasks, and invokes the planner again
only after the batch is exhausted. A discovery by an earlier task does not
interrupt the batch; it is evidence for the next planning cycle.

Implementation and research workers receive one immutable self-contained task
and return free-form human-readable semantic text. The runtime does not parse
that text for orchestration decisions. It independently records changed paths,
verification, attempts, timestamps, and state transitions.

An intermediate verification failure retries the same task with authoritative
failure evidence. When validated `# Done` leads to failed strict final
verification, the failure evidence is supplied to a new planning cycle. `# Done`
itself is never a Factory completion transition. There is no special correction
batch, checkpoint reviewer, mandatory final semantic reviewer, or worker-requested
replan path.

Authoritative state is the minimum machine-owned representation of immutable
completed history, zero or one current task, the ordered current batch,
planning-cycle and attempt budgets, verification, continuations, blockers, and
recovery. Semantic artifacts remain separate human-readable documents. User
answers to planning questions are human-readable runtime artifacts rather than
semantic-control fields in task results. No `plannerDone`, semantic approval,
completion reason, or planner outcome field is added to machine-owned state.

The planner's execution profile can read semantic evidence and current product
reality and write only designated planning output. It cannot mutate product
files, durable intent, or authoritative Factory state.

The new runtime and semantic protocol may introduce a controlled schema-version
break. They do not retain old outcome fields or adapters solely to continue the
previous worker-controlled orchestration model. Persisted planner output is
interpreted under the current protocol, so an old blank result is not
grandfathered as `# Done`.

## Alternatives Considered

- Keep worker outcomes but simplify their JSON: rejected because executors would
  still decide future workflow and runtime would still interpret semantic
  control signals.
- Let executors return `intent-required` or `replan-required`: rejected because
  ordinary workers would again control future workflow and could interrupt an
  immutable planner-authored batch.
- Make the planner classify every missing user decision as durable intent:
  rejected because whether an answer is durable product truth is an IDD concern
  evaluated after the user actually answers; some answers are only local
  implementation choices.
- Cancel and restart the Factory run for every question: rejected because the
  completed history and exact continuation are already durable and a bounded
  planning pause can resume safely without rewriting the original request.
- Replan after every task: rejected because a planner-authored batch is the
  semantic authority until exhausted, and per-task replanning adds cost and
  protocol complexity for uncommon invalidated assumptions.
- Limit every batch to one task: rejected because multiple independent or
  reliably ordered tasks should be contracted in one invocation.
- Require a complete up-front roadmap: rejected because later contracts may
  depend on evidence not yet available.
- Retain checkpoint and final semantic reviewers: rejected because the repeated
  planner evaluates integrated reality and creates any necessary corrections;
  strict deterministic final verification is the terminal gate.
- Infer or migrate every active legacy state: rejected because carrying old
  semantic outcomes forward would preserve the obsolete architecture. An
  incompatible active run is rejected explicitly unless a small versioned
  migration is independently safe.

## Consequences

- Factory can be explained by three ordinary responsibilities: planner identifies
  what remains, executor performs one task and reports what happened, runtime
  executes and verifies the batch before planning again; plus one bounded
  planning-boundary escape hatch when the planner genuinely needs a user
  decision.
- `additional-work-required`, `correction-required`, `global-replan-required`,
  universal semantic-result DTOs, outcome contract matrices, corrective
  routing, checkpoint review, and final semantic review remain absent from the
  normal architecture.
- `# Done` is a minimal explicit semantic conclusion from the existing planner,
  not a new runtime outcome. Runtime checks only its exact protocol form and
  continues through the existing empty-batch representation to strict final
  verification.
- `USER_DECISION_REQUIRED` is not an executor outcome and is not semantic
  orchestration delegated to runtime. The planner supplies only the question;
  runtime supplies pause/resume mechanics.
- The immutable original request remains unchanged. Exact user answers are
  recorded separately and become planning evidence for the same run after any
  required intent update is authorized and completed.
- Research may remain a distinct read-only execution profile but has the same
  free-form result contract and no future-work authority.
- Runtime state and budgets remain semantic-neutral: maximum planning cycles,
  total work items, and attempts per task replace specialized corrective and
  replan counters.
- Planner quality determines batch boundaries. The runtime deliberately accepts
  that a later task may need to adapt to repository changes made by an earlier
  task and relies on the next planner to assess the integrated outcome.
- Completed work remains immutable evidence. Corrections are ordinary tasks in
  a later planner-created batch rather than mutations of history.
- Deterministic blockers, recovery, exact continuations, invocation binding,
  protected artifact ownership, cancellation, and final verification remain
  runtime concerns and do not become semantic report conventions.

## Supersedes

The worker-driven prepend, global-replan, checkpoint-review, corrective-cycle,
and mandatory final semantic-review decisions in the previous accepted version
of this ADR. Durable deterministic runtime ownership and ordered linear
execution remain.

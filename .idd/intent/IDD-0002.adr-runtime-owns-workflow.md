# IDD-0002.adr-runtime-owns-workflow

## Status

Accepted

## Context

The previous Factory topology used fresh LLM coordinator contexts to inspect
persisted artifacts and choose the next operational action. Those choices are
normally derivable from typed state, observable repository state, verification
evidence, and workflow policy. Using semantic agents for them increases cost and
makes recovery and transition correctness harder to enforce.

## Decision

A domain-specific .NET 10 Factory runtime is the sole owner of operational
workflow state and lifecycle. Language models are bounded semantic workers.
Factory Core depends on an agent-backend abstraction; Codex CLI is the first
production backend and all Codex-specific process behavior remains behind that
boundary.

The runtime selects a logical semantic role, the corresponding logical Factory
skill, a backend-neutral execution profile, and dynamic invocation input. The
selected Factory skill is the sole authoritative semantic role contract. Core
does not locate or read installed plugin skill files, construct composite role
prompts, or encode backend-specific skill or sandbox syntax. Each backend
adapter is responsible for exposing and explicitly activating the selected
skill and mapping the execution profile to its own permission mechanics.

The workflow is configured by a constrained YAML composition of registered
Factory primitives. The runtime owns state mutation, validation, authoritative
verification, bounded verification-fix cycles, retry, recovery, review routing,
and finalization. Semantic replanning returns a proposal that the runtime
validates rather than directly changing state.

## Alternatives Considered

- Continue using an LLM step coordinator: rejected because deterministic state
  transitions do not require semantic judgment.
- Build a general workflow framework: rejected because it expands the product
  beyond the bounded Factory domain and weakens safety guarantees.
- Use SQLite for V1 state: rejected because the single-run, single-writer model
  is sufficiently served by atomic filesystem JSON.
- Run implementation workers in parallel: deferred because safe parallelism
  requires worktree, merge, conflict, and integration architecture outside this
  decision.

## Consequences

- Runtime and protocol implementation become packaged product assets and need
  comprehensive deterministic tests.
- Semantic skills become smaller and return validated result artifacts.
- Factory role-definition files are not a second semantic authority; each
  canonical Factory skill contains its complete role contract.
- New agent backends can be added without modifying Factory state machines,
  verification, work-item models, or review routing.
- Legacy active runs must finish with the previous Factory version or be
  cancelled and restarted.

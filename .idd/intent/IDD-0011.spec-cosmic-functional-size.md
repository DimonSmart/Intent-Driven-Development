# IDD-0011.spec-cosmic-functional-size

## COSMIC functional size and indicative effort

The independent target-project-read-only `idd-intent-cosmic` skill estimates the functional size of current numbered Product Intent using COSMIC v5.0 data-movement principles, without inspecting implementation. The default is approximate early sizing; an explicit strict measurement request uses evidence-only COSMIC counting. Neither mode claims certification.

By default the measurement boundary is the complete documented product (including its internal clients, services and logical persistent storage); an explicitly selected area, owner or component sets the requested scope. Count external triggering events and distinct E/X/R/W movements of logical data groups, not internal calls, retries, fields, classes or implementation mechanisms. Each functional process has one normative owning spec; references are connectors, not additional processes or movements. Duplicate normative definitions are structure-audit findings, not silently merged.

In approximate mode, distinguish explicit, logically implied and assumed movements. If a known functional capability is underspecified, automatically adopt the simplest conventional behavior compatible with the requirements. Do not invent independent capabilities or contradict explicit requirements. The storage technology is irrelevant when it plays the same logical persistence role. Count a plausible central estimate and, where materially different plausible interpretations remain, a bounded low/high estimate. Unresolved local gaps must not suppress the supported estimate for other processes. Report excluded/unestimated processes and unread sources explicitly; an estimate of the assessed scope must not masquerade as a full-product estimate. No number is fabricated for a scope with no identifiable process. Strict mode counts only defensible complete processes and labels a partial subtotal when necessary.

Inventory and attempt all current normative specs in the requested scope. Read all accessible sources or reuse explicitly eligible complete extraction snapshots; account for any missing, inaccessible or unprocessed material. Use context isolation, chunking and hierarchical aggregation when needed for scale, not as prerequisites. Sequential or grouped analysis in a single context is allowed when sufficient. Missing child-agent or persistent-cache capabilities alone do not prevent estimation.

Optional external project-specific Markdown extraction packets `IDD-NNNN.cosmic.md` support reuse/resume. A completed packet contains source facts, candidate processes/connectors and evidence, not authoritative CFP, effort or assumed requirements. Write through `.cosmic.partial.md` and publish by successful rename. Reuse matching final packets by default when using cache; disclose unverified freshness; support explicit per-ID/all refresh and cleanup. Refresh recomputes from source; a failed refresh cannot silently use the old snapshot. No required helper script, hashes, generated state database or runtime. No target-project mutation; assumptions never become Product Intent, Factory tasks or acceptance criteria.

The standard result is a compact standalone Markdown report in the conversation (optionally export on explicit request outside target project). Include scope, mode, source coverage, approximate or measured CFP, functional process count, functional-area breakdown (each process assigned once), concise per-process owner/trigger/movement breakdown and material assumptions or gaps. Separate explicit/implied/assumed movements, show a range only where justified, and reconcile areas and totals. Detailed evidence/coverage and coupling are available on request; coupling is not a CFP multiplier.

Report indicative human effort separately from CFP: `person-hours = CFP × hours per CFP`. The default is **3 person-hours/CFP**, a configurable illustrative IDD heuristic, not a calibrated industry norm. A user-supplied positive finite rate or ordered positive rate range overrides the default for the request; display the actual rate and its source, apply it consistently to all totals and propagate CFP/rate bounds. Do not silently select another rate, use team size, convert to elapsed duration, or imply a delivery commitment. No hours when no CFP can be estimated; explicitly partial CFP produces partial hours only. Honor a request for CFP only. Algorithmic and nonfunctional complexity can make the effort model inaccurate; the separate qualitative `idd-intent-estimate` skill remains independent.

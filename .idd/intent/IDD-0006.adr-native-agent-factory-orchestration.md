# IDD-0006.adr-native-agent-factory-orchestration

## Context

Factory decomposes large implementation requests into bounded semantic tasks. Its purpose is to isolate context and incrementally reconsider repository reality, not to provide a durable workflow engine. Long-running children must not consume parent-model tokens through repeated status polling.

## Decision

Use host-native generic agents and a two-level hierarchy: a thin public Supervisor rotates fresh Factory Roots at verified plan boundaries; a Root coordinates fresh isolated Planners and single-task Workers. Keep role instructions in installed internal Skills from the same package, not custom registered agent types or copied protocol bodies.

Use native blocking or event-driven waits. A wait interval is not a child termination or execution deadline; host primitives own child lifecycle and emergency interruption. Avoid recreating a universal runtime when native capabilities are missing. Generic roles avoid dependence on a host-specific registration mechanism.

Semantic decisions belong to agents: task decomposition, replanning and relevance of Product Intent or Conditional Engineering. Deterministic operations own identity resolution, Always Engineering enumeration, policy lookup and lightweight bookkeeping.

Adopt at-least-once semantic convergence against repository reality rather than exactly-once execution or exact replay. Persist only the evidence necessary for safe recovery, not an authoritative workflow state machine. Use an immutable Git baseline and bounded attribution evidence to protect approved decisions and preserve partial work.

The behavioral and precise protocol contracts are owned by IDD-0001; persistent recovery and refinement by IDD-0012; model policy by IDD-0013. Platform-specific spawn/wait arguments, internal Skill paths and naming conventions are maintained in canonical instructions, not duplicated here. Generated adapters may change technical packaging and tool mappings but not canonical workflow meaning (IDD-0003).

## Rationale and experimental evidence

The earlier deterministic .NET runtime solved a real problem: blocking execution prevented expensive parent-model polling. Its MCP/CLI transport was useful while the runtime existed, but native blocking waits make that transport unnecessary.

The runtime accumulated authoritative attempts, state transitions, retries, backend failure classes, process supervision, verification transitions and schema migrations. Exact reconstruction after partially applied semantic changes is fragile. These guarantees suit a workflow execution product but exceed Factory's context-isolation purpose.

Custom role registration proved unreliable across host surfaces: Codex Desktop may omit the custom agent-type parameter and marketplace installs may not register custom roles. Installed internal Skills plus generic native child contexts remove that dependency without relaxing isolation, role loading or Planner read-only semantics. Existing registered user/project roles need not be removed.

A Windows Codex 0.163.0 / PowerShell 7.6 depth-two smoke test established native nesting feasibility. An emergency-interruption experiment observed a shell process continuing after agent abort. This motivates blocking on specifically uncertain Writer liveness and keeping OS cleanup with the host, not requiring forced-cancellation proof for every normal execution. Other hosts need independent evidence; release requires real multi-batch end-to-end evidence. Generation, task names and smoke tests alone do not prove live support.

## Alternatives considered

- A custom durable workflow runtime: stronger central execution guarantees at the cost of operational complexity, schema evolution and adapter coupling.
- Blocking transport around that runtime: removes polling but retains unnecessary custom transport and runtime.
- Registered custom native roles: depend on inconsistent host registration and selection capabilities.
- Exactly-once execution and exact continuation: cannot safely infer partial external side effects from workflow state alone.
- Model-driven polling: consumes parent inference turns without meaningful semantic progress.

## Consequences

Native lifecycle, shared workspace and installed-Skill access, isolation, waiting and trusted completion are required. Exceptional interruption and OS cleanup remain host responsibilities. A missing capability may leave a host unsupported rather than justify a second runtime.

Some unfinished work may be re-executed; fresh Workers must preserve correct partial effects. Root rotation bounds accumulated child transcripts, but the Supervisor still accumulates compact results and has finite context. No fixed token saving or unlimited context is guaranteed.

Factory remains small: no dedicated orchestration runtime, custom MCP transport, persisted state machine, backend failure taxonomy, process supervisor or separate verification engine. Old runtime state is not exactly resumable; repository effects are preserved.

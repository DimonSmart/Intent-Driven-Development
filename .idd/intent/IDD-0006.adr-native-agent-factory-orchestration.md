# IDD-0006.adr-native-agent-factory-orchestration

## Status

Accepted

## Context

Factory exists to split a large semantic implementation request into smaller
pieces that execute in fresh contexts. The previous .NET runtime added process
supervision, MCP transport, state transitions, retries, exact continuation,
verification lifecycle, and status machinery. Much of that complexity managed
agent execution rather than improving semantic decomposition.

Modern hosts can provide native child agents, isolated contexts, shared
repository access, and terminal waiting directly.

## Decision

Factory does not own a deterministic workflow runtime.

Native platform subagents provide semantic context isolation and execution.
Factory owns only this lightweight semantic orchestration loop:

```text
planner
-> current batch
-> fresh worker per task
-> planner
```

The repository is authoritative implementation reality. Factory persistence is
temporary best-effort scheduling and semantic context.

Each planner and worker receives a fresh semantic context with parent transcript
inheritance disabled. Waiting must be native blocking/event-driven rather than a
model-driven polling loop.

Factory deliberately provides at-least-once execution. Interrupted tasks may
execute again, and workers converge from current repository reality.

The planner owns semantic relevance such as `TaskRelatedIntent`; mechanical ID
resolution belongs to the worker or host. The separate
`RelevantCompletedWork` protocol is removed. New tasks are self-contained.

Configured project verification runs after planner `# Done`; a bounded failure
becomes input to a new fresh planner. Factory does not recreate a verification
engine or retry state machine.

The Factory MCP server, packaged .NET runtime, process supervision, runtime
state schema, and Factory-specific transport operations are removed.

## Consequences

Adapters may be unsupported when their native agent APIs cannot satisfy fresh
context, shared repository, non-polling wait, final result, and stop/close
requirements. Universal adapter parity is less important than keeping Factory
small.

A legacy active run cannot be exactly continued across this architecture change.
Its repository effects are preserved; an explicit restart can reuse a valid
persisted request.

Token cost from worker duration should not scale with parent polling turns.
Worker execution logs should remain inside worker contexts instead of
accumulating in the root context.
